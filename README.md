# 组织设计沙盘

给 HRBP / OD 用的第一版可点击沙盘。先导入一张花名册，在画布上看组织，再把岗位拆成任务，标出哪些由人做、哪些由 AI 做，并算出人机比和「人力 + 算力」成本。

这一版用来亲自点一遍、收集反馈。计算都在浏览器里完成。没有配置模型密钥时，不依赖任何后端接口。

## 五分钟体验

1. `npm install && npm run dev`，打开 <http://localhost:3000>。
2. 在导入页点 **「星澜科技 · 完整花名册」** 的「载入」。这是虚构的约 120 人公司。看右侧「AI 做了什么」，确认列名，预览部门树，进入沙盘。
3. 沙盘顶部看人数、层级、平均管理幅度、人力成本和算力成本。点右侧的主动提醒，画布会定位到对应部门。试试搜索「客户成功」、按人数着色、展开和收起。部门之间的紫色协作线默认隐藏，点顶栏「协作视图」才会出现，选择会记在本机。线只连接部门，线越粗表示近 90 天的协作次数越强。点「平台部」看负责人卡片（目标、权重、协作次数）。业务负责人看不到这张卡片。
4. 把「战略部」拖到「职能中心」上，选「挂到下面」或「合并进来」。提醒会马上出现在部门旁边，可以「帮我拆分」「忽略」或「跟 Agent 聊聊」。拆分会先预览，再写入方案。基线只读，改动进入方案 A，可以撤销。把人从左侧名单拖到另一个部门上，会先确认再改上级。
5. 打开 **岗位拆解**，选「客户成功顾问」（12 人）。生成任务清单，把一两项改成「由 AI 做」或「人机协同」，看人机比、释放工时和成本。可以存成模板。
6. 回到导入，载入 **「凌川贸易 · 混乱花名册」**。列名是「汇报人 / 组织单元 / 担任岗位」。处理缺上级、互相汇报和两个张伟，每条都可以一键修或跳过。再载入 **「飞书通讯录」**，同一批人，上级列叫「直线经理」，文件里还有一张部门表。

右上角可以切换查看身份。业务负责人看不到个人薪酬。系统管理员可以改管理幅度、层级和算力单价。

## 本地运行

```bash
npm install
npm run dev
```

`npm run dev` 和 `npm run build` 会把 `sample-data/` 复制到 `public/sample-data/`，页面上的「载入 / 下载」走的是这份副本。

```bash
npm test
npm run lint
npm run generate:samples   # 重新生成示例花名册、协作次数和目标模板
```

## 环境变量

复制 `.env.example` 为 `.env.local`。全部留空即可，应用以**离线演示**运行。

| 变量 | 作用 |
|---|---|
| `LLM_BASE_URL` | OpenAI 兼容接口，例如 `https://api.openai.com/v1`，也可以换成国内兼容网关 |
| `LLM_API_KEY` | 密钥，只在服务端使用，不会打进浏览器包 |
| `LLM_MODEL` | 模型名，默认 `gpt-4o-mini` |

配好之后，对话、列名复核和岗位拆解会先请求 `/api/ai`。失败或返回无法解析时，自动退回规则和模板，界面会标明来源。

## 示例数据

都在 `sample-data/`，页面上可以一键载入，也可以下载。

文件名、工作表名和 `数据标记` 列都会写明 **示例数据**。姓名、公司和金额都是虚构的。

| 文件 | 内容 |
|---|---|
| `00-导入模板-示例数据.csv` | 花名册模板，含可选列 |
| `00-协作统计模板-示例数据.csv` | 列只有人A、人B、消息次数、共同会议次数、OKR对齐次数 |
| `00-目标OKR模板-示例数据.csv` | 目标、上级对齐和关键结果进度 |
| `00-绩效目标权重模板-示例数据.csv` | 只填目标名称和权重，没有评级 |
| `01-星澜科技-花名册-示例数据.xlsx` / `.csv` | 约 120 人。多级部门（如 `研发中心/平台部/数据组`）、职级、年度人力成本。埋了：何清直接带 12 人、马修远只带 2 人、战略部只有 1 人、实时链路小组深 7 层 |
| `02-凌川贸易-混乱花名册-示例数据.csv` | 列名不规范。缺上级、汇报成环、两个张伟 |
| `03-凌川贸易-飞书通讯录导出-示例数据.xlsx` | 同一批凌川贸易员工。成员列表 + 部门列表，上级列名为「直线经理」 |
| `04-星澜科技-协作与目标-示例数据.xlsx` | 星澜科技的协作次数、OKR 和绩效权重。载入花名册时会一起带上 |

协作文件如果带了消息正文、会议纪要、绩效等级或排名列，解析时会丢掉这些列，不进入内存，也不展示。

## 架构

```
浏览器
  导入 / 画布 / 岗位拆解
        │
        ├─ 数据源 RosterSource     文件、粘贴、示例；HRIS 接口留了空实现
        ├─ 列名匹配、部门树推断、一键修复
        ├─ 规则引擎 evaluateRules  幅度、层级、一人/空部门、成环、没有上级
        ├─ 人机比与成本
        ├─ AiProvider              有密钥走 /api/ai，否则用模板和规则
        └─ WorkspaceRepository     现在是 localStorage，撤销栈在内存里
```

- 组织快照是 `people + departments`。方案 A/B/C 是基线的副本，任务拆解写在方案上，不改基线。
- 撤销覆盖导入之后的修改（任务、忽略提醒、重置方案、口径）。快捷键 Ctrl/⌘+Z。
- 规则引擎是纯函数。拖拽或拆分预览之后立刻调用，百人规模会在 1 秒内返回；模型解释是另外一层，不挡规则结果。
- 绩效列可以导入，但界面不展示个人绩效，也不做个人排名。绩效目标只显示权重。
- 协作只保存次数。画布连线是部门对部门。个人之间的次数只出现在负责人卡片里，卡片不显示名次。
- 薪酬和负责人卡片：OD 专家和系统管理员可见。业务负责人只看部门汇总成本和部门间协作线。

## 计算口径

这些是本版对 PRD 里尚未定死的几处的取法，管理员可以改数字。

- **管理幅度过宽**：直接下级多于 8 人。**过窄**：1 或 2 人（1 人同时算单点汇报）。
- **层级数**：最长部门路径的段数。深于 6 层提醒。星澜科技的实时链路小组是 7 段。
- **一人部门**：把子部门算进去之后只有 1 个人。只有负责人、下面还有团队的上级部门不会被误报。
- **平均管理幅度**：有直接下级的人，其下级人数的平均数。
- **人机比** = AI 工时占比 : 人工时占比。人机协同默认各占 50%。
- **释放工时** =（完全由 AI 做的工时 + 协同工时 × 分摊比例）× 月标准工时（默认 160）。这是理论上能腾出来的时间，**不自动减人**。
- **算力成本** = 使用了 AI 的任务数（「由 AI 做」和「人机协同」各算 1 条）× 单价 × 12。单价默认 200 元 / 任务 / 月。纯人工任务不计费。
- **岗位总成本** = 该岗位仍在编的年度人力成本 + 年算力。多人同岗共用一份任务清单，汇总时按人数相加。
- **协作强度** = 0.4×消息次数 + 0.4×共同会议次数 + 0.2×OKR 对齐次数。每一项先在本批配对里按最大值归一到 0–100。某一项空着时，用剩下几项的原权重重新归一。窗口默认 90 天。同一部门内的配对不画到画布上。

## 这一版没有做

- 右键菜单里的新建部门、删除部门和虚线汇报
- P5 方案对比、P6 审批和文档导出
- 真实的飞书 / 钉钉 / 企微接口。`createHrisRosterSource` 会明确告诉用户本期用表格。协作次数目前来自 Excel 模板

## 部署

按 Next.js 部署到 Vercel 即可：`npm run build`。不配密钥时，页面打开后的组织计算全部在浏览器里完成，`/api/ai` 会返回未启用。密钥放在 Vercel 的环境变量里，不要写进仓库。
